# KingKlaw

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md)

**このプラグインを読み込んでよいか**——答えるのはこの一問だけの小さなライブラリです。

判定を行う中核は SPARK/Ada で書かれ、gnatprove で形式検証されています。

## 六つの事実

| 事実 | 問い | 値 |
|---|---|---|
| Operator | 人間が**いま**、**これを**明示的に要求したか | `requested` · `absent` |
| Origin | ホストが信頼する認証者が、この識別子とこのバイト列の対応を保証しているか。その保証は今も有効か | `attested` · `unattested` · `revoked` |
| Integrity | バイト列は保証された内容と実際に照合されたか | `verified` · `mismatch` · `unchecked` |
| Proof | 機械検査された証明はあるか。ここで再検証したか、同梱されてきただけか | `reproved` · `carried` · `absent` |
| Floor | このホストはどの証明水準を要求するか | `floor_reproved` · `floor_carried` · `floor_none` |
| Containment | ホストが強制できる境界の内側で動くか | `contained` · `uncontained` |

## 何が違うのか

六つの事実の組み合わせは **324 通りあり、そのすべてに証明済みの判定があります**。

拒否は「テストしたら拒否された」ではなく**定理**です。事後条件がどの事実から
どの拒否が導かれるかを明示しているため、後の変更で拒否が黙って許可に変わること
はありません——証明が落ちます。

gnatprove level 2、`pragma Assume` なし、`SPARK_Mode` を切った箇所なし、
justified check なし。証明の記録は `admission/PROVE.txt`、再検証の手順は
`admission/REPROVE.md` にあり、ご自身で走らせて確認できます。

中核は**時計を読まず、ファイルを開かず、メモリを確保せず、状態を持ちません**。
六つの事実が成立したときに**何が帰結するか**だけを決めます。
**事実を確立するのはホスト側の仕事です**——ハッシュを取らずに `verified` と
答えたホストは、得るべきでない許可を得ます。どんなライブラリにもこれは防げません。
防げるふりをすることこそが本当の欠陥なので、文書に明記してあります。

## 三つの組み込み方

1. **Ada**：パッケージを `with` し、`.gpr` を取り込む。契約が一緒に来る唯一の
   経路で、gnatprove が**あなたの使い方**まで証明できます。
2. **C**：`admission/include/claw_admit.h`。共有ライブラリは二つの記号を公開します。
3. **別プロセス**（推奨）：六語を渡し、一語が返る。
   終了コード `0` 許可 / `1` 拒否 / `2` 引数不正。

三番目なら Go、Rust、TypeScript のホストでも **Ada ツールチェーンなしで**
この証明済み判定器を使えます。別プロセスなので **AGPL があなたのプログラムの
ライセンスに及ぶこともありません**。読み込まれたプラグインが書き換えられる
プロセスの中に判定器を置いても、それは門とは呼べません。

## 正直な限界

- Alire クレートはまだありません。clone してビルドしてください。
- ビルド済み共有ライブラリは macOS arm64 のみ。Linux と Windows は
  ソースからビルドが必要です（スクリプトとダイジェストは同梱）。
- サンドボックスが無いと正直に答えると、**ネイティブプラグインはほぼすべて
  拒否されます**。これは壊れているのではなく正しく働いている状態ですが、
  導入は差し込むだけでは済まず設計上の議論になります。
- Ada ソースは不変のビルド成果物の vendored コピーです。各ファイルの先頭に
  派生元の sha256 が記録されており、信用ではなく照合ができます。

## ライセンス

AGPL-3.0-or-later。真理値表は `FITTING.md` に印刷してあります。それを見て
ご自身で判定器を書いてくださっても構いません。そのコードに当方の権利は
一切及びません。意図的にそうしています——重要なのはコードではないからです。
