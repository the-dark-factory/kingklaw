# KingKlaw

[English](README.md) · [简体中文](README.zh-CN.md)

一個很小的函式庫，只回答一個問題：**這個外掛到底能不能載入。**

判定核心是 SPARK/Ada 寫的，經過 gnatprove 形式化驗證。

## 六個事實

| 事實 | 問題 | 取值 |
|---|---|---|
| Operator | 有沒有人**明確**要求安裝這一個東西，**現在**？ | `requested` · `absent` |
| Origin | 本機信任的某個授權方，有沒有為「這個身分對應這些位元組」背書？還算數嗎？ | `attested` · `unattested` · `revoked` |
| Integrity | 位元組有沒有真的和背書的內容核對過？ | `verified` · `mismatch` · `unchecked` |
| Proof | 有沒有機器檢查過的證明？是在本機重新驗證的，還是隨套件帶來的？ | `reproved` · `carried` · `absent` |
| Floor | 本機要求什麼證明標準？ | `floor_reproved` · `floor_carried` · `floor_none` |
| Containment | 它會不會跑在本機能強制執行的邊界內？ | `contained` · `uncontained` |

## 為什麼值得一看

六個事實共 **324 種組合，每一種的判定都經過形式化證明**。

拒絕的理由是**定理**，不是「我們測過」。後置條件寫明了哪些事實導出哪一種拒絕，
所以後來的修改不可能讓一個拒絕悄悄變成放行——那樣證明會直接失敗。

gnatprove level 2，沒有 `pragma Assume`，沒有關掉 `SPARK_Mode`，沒有
justified check。證明紀錄在 `admission/PROVE.txt`，重新驗證的步驟在
`admission/REPROVE.md`，你可以自己跑一遍。

核心**不讀時鐘、不開檔案、不配置記憶體、不保存狀態**。它只決定「六個事實成立
之後會推出什麼」。**建立這些事實是宿主自己的責任**——如果宿主沒有做雜湊就回答
`verified`，它會得到一個不該得到的放行，任何函式庫都攔不住這一點。文件裡明說了
這一條，假裝能攔住才是真正的缺陷。

## 三種接入方式

1. **Ada**：`with` 這個套件，引 `.gpr`。只有這條路徑會把契約一起帶過來——
   gnatprove 可以證明**你對這個判定器的用法**，而不只是判定器本身。
2. **C**：`admission/include/claw_admit.h`，動態函式庫匯出兩個符號。
3. **獨立行程**（建議）：六個詞進去，一個詞出來，
   離開碼 `0` 放行 / `1` 拒絕 / `2` 參數不合法。

第三種方式表示 Go、Rust、TypeScript 寫的宿主都能用這個證明過的判定器，
**不需要安裝 Ada 工具鏈**。而且因為是獨立行程，**AGPL 不會影響你自己程式的
授權條款**。把判定器放在一個「任何已載入外掛都能改寫它」的行程裡，本來也算不上
一道門。

## 老實說的短板

- 還沒有 Alire 套件；目前需要 clone 後自己建置。
- 預先建置的動態函式庫只有 macOS arm64。Linux 與 Windows 需自行編譯，
  建置指令碼與摘要都在儲存庫裡。
- 如果你誠實回答「沒有沙箱」，它幾乎會**拒絕所有原生外掛**。這是它正常運作，
  不是壞掉——但也表示導入它是一次架構討論，不是隨插即用。
- Ada 原始碼是不可變建置產物的 vendored 副本，每個檔案開頭都記錄了它所衍生的
  來源檔 sha256，你可以核對衍生關係，而不是選擇相信。

## 授權條款

AGPL-3.0-or-later。真值表印在 `FITTING.md` 裡——你完全可以照著自己寫一個判定器，
那份程式碼與我們沒有任何關係。這是刻意的：重點從來不是這段程式碼。
