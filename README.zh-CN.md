# KingKlaw

[English](README.md)

一个很小的库，只回答一个问题：**这个插件到底能不能加载。**

判定核心是 SPARK/Ada 写的，经过 gnatprove 形式化验证。

## 六个事实

判定器接收六个事实，每个事实的取值都是封闭的：

| 事实 | 问题 | 取值 |
|---|---|---|
| Operator | 有没有人**明确**要求安装这一个东西，**现在**？ | `requested` · `absent` |
| Origin | 本机信任的某个授权方，有没有为「这个身份对应这些字节」背书？还算数吗？ | `attested` · `unattested` · `revoked` |
| Integrity | 字节有没有真的和背书的内容核对过？ | `verified` · `mismatch` · `unchecked` |
| Proof | 有没有机器检查过的证明？是在本机重新验证的，还是随包带来的？ | `reproved` · `carried` · `absent` |
| Floor | 本机要求什么证明标准？ | `floor_reproved` · `floor_carried` · `floor_none` |
| Containment | 它会不会跑在本机能强制执行的边界内？ | `contained` · `uncontained` |

## 为什么值得一看

六个事实一共 **324 种组合，每一种的判定都经过形式化证明**。

拒绝的理由是**定理**，不是「我们测过」。后置条件写明了哪些事实导出哪一种拒绝，
所以后来的修改不可能让一个拒绝悄悄变成放行——那样证明会直接失败。

gnatprove level 2，没有 `pragma Assume`，没有关掉 `SPARK_Mode`，没有
justified check。证明记录在 `admission/PROVE.txt`，重新验证的步骤在
`admission/REPROVE.md`，你可以自己跑一遍。

核心**不读时钟、不开文件、不分配内存、不保存状态**。它只决定「六个事实成立之后
会推出什么」。**建立这些事实是宿主自己的责任**——如果宿主没有做哈希就回答
`verified`，它会得到一个不该得到的放行，任何库都拦不住这一点。文档里明说了这一
条，假装能拦住才是真正的缺陷。

## 三种接入方式

1. **Ada**：`with` 这个包，引 `.gpr`。只有这条路径能把契约一起带过来——
   gnatprove 可以证明**你对这个判定器的用法**，而不只是判定器本身。
2. **C**：`admission/include/claw_admit.h`，动态库导出两个符号。
3. **独立进程**（推荐）：六个词进去，一个词出来，
   退出码 `0` 放行 / `1` 拒绝 / `2` 参数不合法。

第三种方式意味着 Go、Rust、TypeScript 写的宿主都能用这个证明过的判定器，
**不需要装 Ada 工具链**。而且因为是独立进程，**AGPL 不会影响你自己程序的许可证**。
把判定器放在一个「任何已加载插件都能改写它」的进程里，本来也算不上一道门。

## 老实说的短板

- 还没有 Alire 包；目前需要 clone 后自己构建。
- 预编译的动态库只有 macOS arm64。Linux 和 Windows 需要自己编译，
  构建脚本和摘要都在仓库里。
- 如果你如实回答「没有沙箱」，它几乎会**拒绝所有原生插件**。这是它在正常工作，
  不是坏了——但这也意味着接入它是一次架构讨论，不是即插即用。
- Ada 源码是不可变构建产物的 vendored 副本，每个文件头部都记录了它所派生的
  源文件 sha256，你可以核对派生关系，而不是选择相信。

## 关于访问速度

GitHub 在部分地区访问较慢。仓库很小（源码几百 KB），也可以只下载某个 tag 的
压缩包。如果你愿意在 Gitee 上做一个镜像，请自便——许可证允许，我们也不介意。

## 许可证

AGPL-3.0-or-later。真值表印在 `FITTING.md` 里——你完全可以照着自己写一个判定器，
那份代码和我们没有任何关系。这是有意为之：重点从来不是这段代码。
